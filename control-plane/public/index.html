01

What CVBench measures

A leaderboard with receipts.

Every new public submission runs the declared 16-scenario Version 3 suite at native pace: the same 13 deterministic synthetic tests and three exhaustive, full-frame, native-30-FPS real-video sequences, now with 4 CPUs, 8 GiB RAM, and a 240-second run budget. Native source time never changes. Accuracy, cgroup CPU-seconds per source-second, real-time factor, RAM, I/O, backlog, and deadline misses remain separate Pareto axes—there is no hidden blended score.

A

Accuracy

Class-aware detection, HOTA, IDF1, localization, identity association, misses, and false tracks against frame-level ground truth.

R

Robustness

Acquisition, visible retention, identity continuity, occlusion recovery, and fault response.

L

Latency

Receive time minus source-frame time, recorded by the harness—not self-reported by the submitted system.

Ω

Resources

Container/cgroup CPU time, CPU-seconds per native source-second, memory, I/O, process count, and real-time factor sampled outside the submitted system. GPU data appears only for an isolated device.

!

Diagnostics

Structured findings and portable evidence packets for the largest observed failures.

02

The exact container contract

Bring one immutable Linux image.

The image is a packaging, reproducibility, and security boundary—not a one-model or one-process assumption. Submitted code runs only on ephemeral GitHub-hosted Linux runners; Cloudflare never executes it.

1

Freeze the image

The CLI uploads a private immutable Docker archive directly. Maintained projects may still submit a public linux/amd64 registry digest.

2

Connect and become ready

Your single- or multi-process system reads CVBENCH_INPUT_SOCKET, connects to the progressive socket, then prints exactly CVBENCH_READY as one stdout line.

3

Consume ordered frames

The same Unix stream stays open for the sequence. Detector + tracker pipelines may retain temporal memory, association state, filtering, and post-processing. Messages contain lengths, JSON metadata, then JPEG bytes.

4

Emit tracks

Print one cvbench.track/v1 JSON object per stdout line. Put logs on stderr. The envelope is one linux/amd64 image, network disabled, 4 CPUs, 8192 MB total memory, a 240-second run budget, one socket-directory mount, no extra mounts, and no Docker socket.

STANDARD LAYOUT / V1

container
├── your runtime + weights
├── argv: ["python", "serve.py"]
└── environment
    └── CVBENCH_INPUT_SOCKET
        = /run/cvbench/input.sock

/run/cvbench/        # only mount
└── input.sock        # streaming input

stdout                # protocol only
stderr                # diagnostics
network               # disabled
CPU / memory           # 4 / 8192 MB
maximum run time       # 240 seconds

API and automation

Prefer a script or agent? Use the exact same idempotent endpoint.

POST /api/v1/submissions
curl -sS "$CVBENCH_API_BASE_URL/api/v1/submissions" \
  -H "Authorization: Bearer $CVBENCH_API_KEY" \
  -H "Idempotency-Key: my-system-v7-001" \
  -H "Content-Type: application/json" \
  --data '{
    "image": "ghcr.io/acme/tracker@sha256:0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
    "argv": ["python", "-m", "tracker"],
    "name": "Acme Temporal Tracker",
    "model_version": "7.0"
  }'
import os, uuid, requests

response = requests.post(
    f"{os.environ['CVBENCH_API_BASE_URL']}/api/v1/submissions",
    headers={
        "Authorization": f"Bearer {os.environ['CVBENCH_API_KEY']}",
        "Idempotency-Key": str(uuid.uuid4()),
    },
    json={
        "image": "ghcr.io/acme/tracker@sha256:...",
        "argv": ["python", "-m", "tracker"],
        "name": "Acme Temporal Tracker",
        "model_version": "7.0",
    },
    timeout=30,
)
response.raise_for_status()
print(response.json()["id"])
Goal: improve this model against CVBench.

1. Read /api/v1/contract and create a Dockerfile plus optional
   cvbench.yaml in the model directory.
2. Run: cvbench validate .
3. Run: cvbench submit . --wait --json
4. Keep the returned result_url for the supervising person.
5. Read feedback.priorities, scores, and findings.
6. Change one model variable, increment the version, and submit again.

stdout is stable JSON. Human-readable build and progress events use stderr.
Identical retries use the same content-derived idempotency identity.
One-time setup: cvbench login stores the credential in macOS Keychain (or an owner-only config file on Linux). Agents use it without printing or copying secrets into their prompts.

Security boundary

The queue is not the sandbox.

The control plane validates intent. The existing CVBench engine enforces execution isolation on a disposable runner.

01Cloudflare WorkerStatic assets, API validation, authentication, rate limits, and D1 state only.

02GitHub-hosted runnerLeases one job, pulls the exact digest, runs CVBench, and posts the report back.

03Tested containerNo network, no Docker socket, an unprivileged UID/GID, CPU and memory caps, and only the progressive socket mount.

04Secret separationRunner and callback tokens stay in the host process environment and are removed from the benchmark subprocess environment.
